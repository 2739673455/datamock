# 金融智能客服系统项目实战需求说明
## 1. 项目背景与目标
### 1.1 项目背景
金融服务平台面向个人客户和企业客户提供账户管理、银行卡、存款、贷款、理财、基金、信用卡、支付转账等一站式金融服务，覆盖开户、交易、资金管理、产品购买、售后服务等完整业务链路。

随着金融业务规模不断扩大，客户在账户查询、产品咨询、交易查询、贷款办理、信用卡服务、售后处理等方面的咨询量持续增长，需要构建一套智能客服系统，承担高频业务咨询和任务办理，提高客户服务效率并降低人工客服压力。

------

### 1.2 项目目标
构建一个面向金融行业的智能客服系统，支持以下核心目标：

- 自动识别客户咨询意图，提供账户、银行卡、贷款、理财、基金、信用卡等业务咨询能力
- 支持贷款申请、信用卡挂失、投诉工单等需要多轮引导的任务型对话
- 在多轮对话过程中持续收集和利用上下文信息（客户身份、银行卡号、贷款编号、交易流水号等）
- 所有对话状态可持久化，支持会话恢复和历史回溯

------

# 2. 用户角色
## 2.1 客户
系统核心服务对象，通过智能客服咨询金融产品、查询账户信息、办理业务、申请贷款、提交投诉等。

------

## 2.2 客服人员
处理系统无法自动完成的问题，负责复杂业务办理、风险审核、投诉处理和人工兜底。

------

## 2.3 运营人员
维护知识库、FAQ、业务流程配置以及金融产品信息，保障客服系统稳定运行。

------

# 3. 功能需求
## 3.1 信息检索
系统能够从业务系统和知识库检索相关信息，并组织自然语言回复，支持金融产品咨询、账户查询、交易查询、政策咨询等业务。

支持：

- 实时业务数据查询
  - 银行账户
  - 银行卡
  - 信用卡
  - 存款
  - 贷款
  - 理财产品
  - 基金产品
  - 交易流水
  - 转账记录
- FAQ 检索
  - 利率说明
  - 手续费规则
  - 提前还款政策
  - 信用卡还款规则
  - 风险提示
- 知识库检索
  - 产品介绍
  - 使用指南
  - 金融政策
  - 常见问题

------

## 3.2 任务型对话
系统应通过多轮对话，引导客户完成需要收集多个业务信息的任务。

支持：

### 账户查询
收集客户身份或银行卡号

→ 查询账户余额

→ 返回账户信息、可用余额、冻结金额等

------

### 交易查询
收集账户号、交易日期

→ 查询交易流水

→ 返回交易金额、时间、交易对象等信息

------

### 贷款申请
收集：

- 贷款类型
- 贷款金额
- 贷款期限
- 用途

提交贷款申请，并返回申请编号。

------

### 信用卡挂失
收集：

- 信用卡号
- 挂失原因
- 身份验证信息

提交挂失申请并反馈处理结果。

------

### 投诉工单
收集：

- 工单类型
- 关联交易号
- 问题描述

创建投诉工单并返回工单编号。

------

# 3.3 对话管控
系统应具备完整的多轮对话管理能力。

支持：

- 槽位收集
  - 主动询问银行卡号、交易流水号、贷款编号等缺失信息
- 上下文保持
  - 持续利用客户身份、账户信息、交易信息等上下文
- 流程切换
  - 当前办理贷款时，可切换处理余额查询等新任务
- 流程恢复
  - 新任务完成后恢复原流程
- 流程取消
  - 用户取消当前业务后清理对应状态

------

## 3.4 闲聊兜底
当客户输入与金融业务无关的问题时，系统能够自然回复，并适当引导客户回到业务办理场景。

------

# 4. 典型业务场景
## 4.1 产品咨询
客户咨询贷款、理财、基金、信用卡等产品信息。

产品类型包括：

- 存款产品
  - 利率
  - 起存金额
  - 存期
- 理财产品
  - 风险等级
  - 收益率
  - 起购金额
- 基金
  - 基金类型
  - 净值
  - 风险等级
- 信用卡
  - 年费
  - 权益
  - 信用额度
- 贷款
  - 利率
  - 最长期限
  - 还款方式

```
客户：有没有适合稳健投资的理财产品？

系统：
返回符合条件的理财产品列表、风险等级、预期收益率，
并引导客户查看产品详情。
客户：
信用卡金卡和白金卡有什么区别？

系统：
返回两种信用卡的额度、权益、年费及适用人群。
```

------

# 5. 对话交互要求
## 5.1 消息处理
- 支持文本消息
- 支持业务对象消息（银行卡、账户、贷款、交易记录等）
- 收到业务对象时，自动提取业务信息并填充当前任务所需槽位

------

## 5.2 响应模式
支持：

- 非流式响应
- SSE 流式响应

------

## 5.3 会话管理
支持：

- 创建新会话
- 查询历史消息
- 查询当前会话状态（当前任务流程、槽位信息）
- 会话状态持久化存储
- 会话恢复

------

## 5.4 意图澄清
系统无法准确判断用户需求时，应主动澄清，包括：

- 同时匹配多个业务意图
- 用户输入过于模糊
- 当前任务缺少关键业务信息
- 用户输入与当前任务上下文冲突

------

# 6. 非功能需求
## 6.1 可靠性
- 单次对话失败不影响整体服务
- 外部金融业务 API 支持超时、重试及异常处理
- 对话状态保存失败具备降级能力

------

## 6.2 可观测性
能够追踪整个对话处理链路：

- 意图识别结果
- Agent 执行过程
- 工具调用记录
- 工作流节点
- 回复生成过程
- 状态更新

支持关键节点日志记录与审计。

------

## 6.3 准确性
- 查询结果基于实时业务数据
- 槽位提取准确
- FAQ 和知识库优先返回最匹配内容
- 金融业务回复符合最新业务规则

------

## 6.4 可扩展性
- 新增业务流程支持配置化扩展
- 新增知识类型可灵活接入
- 新增业务 API 可快速集成
- 支持新增金融产品类型（保险、证券、外汇等）

------

# 7. 项目交付物
- 对话接口与会话管理能力
- 一套可运行的金融业务样本数据与配置
- 前端调试/演示页面
- 项目说明文档与启动说明

------

# 8. 验收标准
1. 能够完成账户、银行卡、贷款、理财、基金、信用卡等业务咨询。
2. 能够在多轮对话中持续收集并利用客户身份、银行卡号、交易流水号、贷款编号等槽位数据。
3. 能够完成贷款申请、信用卡挂失、投诉工单等完整任务流程。
4. 能够完成一次完整的“用户提问 → 意图识别 → 业务查询/流程处理 → 生成回复 → 状态更新”闭环演示。
5. 对话状态可持久化，支持会话恢复。

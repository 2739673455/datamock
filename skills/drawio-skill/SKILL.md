# Draw.io 图表绘制与编辑
## 使用范围
- 创建新的 `.drawio` 架构图、流程图、组件关系图、ER 图、UML 图、时序图
- 修改已有 `.drawio` 的内容、布局、样式、连线、分组和导出文件
- 根据代码、文档、项目目录或用户说明梳理系统结构并生成图表

## 工作原则
- 优先保留用户已经调好的布局，只做必要的局部修改
- 只有用户明确要求重画、布局方向改变或原图结构不可维护时，才重新生成整张图
- 图表表达使用宏观职责和流程阶段，避免把类名、方法名、字段名、接口路径堆到主节点里
- 每个节点只表示一个职责、组件、状态或操作
- 技术名只在必要位置保留；实现细节集中放到技术支撑区或说明块
- 修改完成后导出预览图并做视觉检查

## 基本流程
- 先确认图表目标、范围、输出位置和是否基于已有文件
- 读取现有 `.drawio` 时，优先通过 `mxCell` 的 `id`、`value`、`parent`、`source`、`target` 定位元素
- 编辑已有图时，直接修改对应 `mxCell`，不要为了单点改动重建整图
- 新建图时，先规划泳道、层级、节点和主路径，再写入 `.drawio`
- 完成后导出 PNG 草稿，检查布局、连线、遮挡、文本裁剪和整体可读性

## 文案要求
- 主流程节点使用中文职责名，例如“提交用户消息”“会话编排层”“结构化结果校验”“执行业务动作”
- 节点标题优先使用业务语言和架构语言，少用代码语言
- 技术名作为辅助信息出现，例如 `FastAPI`、`MySQL`、`Redis`、`WebSocket`、`LLM`、`RAG`
- 接口路径、类名、函数名、字段名不放在主流程节点中，除非用户明确要求代码级视图
- 大段说明文字放在独立文本块，不放进流程节点
- 问题块、答案块、备注块要贴近对应节点或流程

## 布局要求
- 节点之间不能重叠，问题块、答案块、说明块也不能遮挡主流程
- 同一层级的节点水平或垂直对齐
- 固定格式元素使用稳定尺寸，避免文本变化导致布局漂移
- 坐标和尺寸优先使用 10 的倍数，方便后续手工调整
- 节点间至少保留可走线空间；复杂区域预留 80px 左右路由走廊
- 主流程尽量从左到右或从上到下，不要混用多个主方向
- 跨泳道或跨区域的长线走外侧通道，不穿过图表中部
- 大图使用泳道或容器分区，分区标题清晰，主体区域按用户需要设置透明或非透明
- 架构分层、职责分区、能力模块不等于时间先后流程，不能为了好看强行用箭头串起来；需要表达职责划分时使用网格、分组或小标题说明
- 串讲文本块、说明块高度要贴合实际文字量，不能留下大面积空白；压缩说明块后同步压缩泳道或页面高度
- 串讲文本不要集中堆在图底部；按业务场景、系统入口、任务执行、分析编排、质量校验、数据账本等主题拆成独立说明块，放在对应泳道或节点附近
- 说明块放进对应泳道时，要预留固定右侧或下方说明区，不要让说明块挤压主流程节点或占用主走线路径
- 同一排跨泳道连接的节点中心线要对齐，避免 draw.io 自动生成不必要折点
- 横向主流程节点尽量保持同一 y 坐标和相近高度，跨栏线优先直连
- 跨栏直连的源节点和目标节点要保持同一中心线，跨栏箭头直接进入目标节点边框
- 同一区域内的数据对象、日志、看板不强行做网状汇聚，优先按“业务对象 -> 业务结果 -> 审计日志 -> 看板”排成清晰链路
- 上下两排节点之间需要连线时，优先从上排末端节点向下进入下排节点，避免垂直线压在中间节点文字上
- 判断节点附近要预留比普通节点更大的上下左右空白；如果分支线或标签贴近节点，优先拉高泳道或移动分支目标节点，不要压缩判断节点和分支线
- 判断节点的上下分支要给出足够垂直距离；下方目标节点不要贴着菱形，避免标签和箭头挤在节点边缘

## 连线要求
- 线条不能穿过节点、标题、问题块、答案块或说明块
- 两个相邻且同层级节点之间尽量使用直线连接
- 箭头指向目标节点的边，不要与目标节点边框平行贴边
- 跨泳道线出现多余折点时，优先对齐两端节点中心线并清理手工路由点
- 横向相邻节点之间的连线要从右边框进入左边框，不要从节点中心或文字区域穿过
- 存储形状、圆柱形节点连线容易视觉上压过文字，连接时显式设置出入口或调整为上下链路
- 多条线连接同一节点时，分配不同入口和出口，避免重叠
- 使用正交线表示流程，减少不必要的折点
- 必须跨线时，优先调整布局；无法避免时使用跨线圆弧或明显分层
- 边标签放在空白处，并使用背景色避免和线条混在一起
- 跨泳道线如果只是从左侧流程进入右侧流程，优先连接右侧泳道的第一个节点，再由泳道内部展开后续链路，避免多条外部线直接打到中间节点造成交叉
- 多个数据节点汇入审计、日志、看板时，不要让多条线在节点中心交叉；优先改成清晰链路，例如“业务对象 -> 结果 -> 审计日志 -> 看板”
- 调整节点位置后要清理旧的 `mxGeometry/Array/as=points` 手工路由点，避免保留旧折点导致线条绕行或覆盖文本块
- 发现线条贴近或覆盖文本块时，先移动节点或改直线通道，不要只增加折点绕线
- 跨区域箭头未贴到目标节点时，设置明确目标节点和目标入口，导出后检查箭头端点是否落在节点边上
- 判断节点的左右主路径优先使用平直水平线；如果正交线自动生成小折点，改用直线样式或重新对齐两端中心线
- 判断节点的下分支优先使用垂直直线；如果线太短、标签贴边或箭头贴着目标节点，增加节点间距或拉高泳道
- 边标签不能压在线条拐点、箭头端点或节点边框上；分支标签放在线段中部空白处，必要时移动标签偏移量
- 不为表达“落库、检查点、审计”添加过多跨泳道辅助线；如果辅助线造成悬空折线、穿越节点或视觉歧义，删除辅助线，保留数据区内部主链路表达事实落点
- 修改节点位置后，不只检查源和目标节点，还要检查所有跨泳道长线的绝对坐标点；泳道下移或加高后要同步更新外侧通道坐标

## 容器要求
- 逻辑分组使用 swimlane 或容器，不要只把节点压在大矩形上
- 容器内子节点使用容器作为 `parent`
- 子节点坐标相对于容器
- 不需要参与连接的容器设置为不可捕获连线
- 泳道和大分区容器使用直角样式
- 泳道标题要可读，不能被线条覆盖
- 多个泳道同屏出现时，泳道本体样式必须统一；如果泳道填充统一为白色，泳道边框和标题文字也要统一，不要只改填充色
- 泳道可以用标题区分区域，不要依赖不同泳道背景色表达区域；节点和图例负责表达类型颜色
- 图例优先使用一行彩色节点，左侧单独放“图例”文字，样式参考 `面试题/客服项目.drawio`
- 图例项直接使用和图中节点一致的填充色、边框色和文字色，不使用“颜色方块 + 文案”的组合样式
- 图例项数量较少时不包容器，直接放在标题区或图表上方空白处

## 样式要求
- 同类节点使用一致颜色和形状
- 说明块、提示块、问题块和答案块统一使用圆角样式
- 同一用途的说明块必须完全统一视觉属性，包括填充色、边框色、文字色、字号、圆角、内边距和对齐方式
- 泳道和串讲说明块如果都作为结构容器使用，应采用同一套低干扰样式，例如白底、灰边、深色文字；不要让它们和业务类型节点争夺视觉注意力
- 统一样式时要检查“所有肉眼可见属性”，不能只统一填充色；边框色、标题文字色、说明块边框色、阴影和圆角都要一起检查
- 页眉标题、副标题和图例左侧标签可以使用纯文本样式
- 架构分层、职责划分这类小标题使用纯文本样式
- 数据留痕类节点使用圆角节点样式
- 判断节点使用菱形
- 数据库、缓存、文件存储使用存储形状
- 外部系统、业务系统、第三方服务要和内部模块有视觉区分
- 问题块和答案块使用不同背景色；折叠答案块展开后允许覆盖流程图时，确保其位于上层

## 导出要求
- 使用本机可用的 draw.io CLI 导出预览
- 当前环境通过 Windows 侧 draw.io CLI 导出，路径为 `/mnt/c/Program Files/draw.io/draw.io.exe`
- 在 WSL 中调用 Windows 侧 draw.io CLI 时，优先用 `wslpath -w` 把输入和输出路径转成 Windows 路径
- 草稿 PNG 不使用 `-e`
- 草稿 PNG 使用 `--width 2000`
- 草稿文件使用单扩展名，例如 `diagram.png`
- 最终交付说明 `.drawio` 源文件和导出文件路径

```bash
drawio -x -f png --width 2000 -o diagram.png input.drawio
drawio -x -f png -e -o diagram.drawio.png input.drawio
drawio -x -f svg -e -o diagram.svg input.drawio

DRAWIO_CLI="/mnt/c/Program Files/draw.io/draw.io.exe"
"$DRAWIO_CLI" -x -f png --width 2000 -o "$(wslpath -w diagram.png)" "$(wslpath -w input.drawio)"
"$DRAWIO_CLI" -x -f png -e -o "$(wslpath -w diagram.drawio.png)" "$(wslpath -w input.drawio)"
"$DRAWIO_CLI" -x -f svg -e -o "$(wslpath -w diagram.svg)" "$(wslpath -w input.drawio)"
```

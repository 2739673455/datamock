# 金融问数系统项目实战需求说明
## 1. 项目背景
面向金融业务场景，建设一个智能问数系统，使业务人员能够通过自然语言完成数据查询、指标统计和趋势分析。系统需要降低数据分析门槛，让用户无需编写 SQL 也能快速获得客户、账户、交易、理财、信贷、还款、逾期、风控、催收和运营相关的数据结果。

金融业务数据覆盖零售银行、消费信贷和财富管理等场景，包括客户开户注册、实名认证、账户管理、资金交易、理财申购赎回、贷款申请、授信审批、合同放款、还款计划、逾期记录、风控规则、反洗钱、人工复核和催收处置等完整业务链路。

## 2. 项目目标
构建一个面向金融场景的智能问数系统：
- 支持通过自然语言完成指标查询和统计分析
- 支持返回结构化结果和统计结果
- 支持围绕客户、账户、交易、理财、信贷、还款、风控和催收等主题进行分析
- 为后续扩展更多金融指标、风险分析能力和经营决策能力提供基础架构

## 3. 角色说明
### 3.1 主要使用对象
- 运营人员：查询新增客户、活跃客户、开户数、交易金额、交易笔数、渠道表现等经营指标
- 产品运营人员：查询账户产品、贷款产品、理财产品、服务产品的销售、持仓、申请和使用情况
- 理财业务人员：查询理财产品申购、赎回、持仓规模、收益、风险等级和适当性匹配情况
- 信贷业务人员：查询贷款申请、授信审批、放款金额、贷款余额、合同状态和还款情况
- 风控与催收人员：查询风险事件、规则命中、黑名单、反洗钱案件、逾期合同、催收案件和回收率等指标
- 管理人员：查看核心指标、风险变化、业务趋势和阶段性分析结果

### 3.2 协同角色
- 数据运营：维护指标口径、字段释义、表关系、业务枚举和问数规则
- 分析人员：校验系统输出结果，补充复杂分析逻辑和风险解释口径
- 技术人员：维护数据接入、元数据管理、查询执行、权限控制和系统稳定性

## 4. 功能范围
系统当前阶段需要至少支持以下能力：
- 构建语义信息：构建金融业务表元数据的语义信息，包括字段释义、指标信息、表关系、业务状态和枚举口径等
- 客户指标查询：查询新增客户数、活跃客户数、客户风险等级分布、KYC 完成情况、个人/企业客户数量等核心指标
- 账户与交易分析：查询正常账户数、新增账户数、交易金额、交易笔数、失败交易笔数、账户余额、冻结金额、渠道交易等数据
- 理财业务分析：查询理财产品数量、理财订单金额、理财持仓规模、持仓数、申购赎回情况、产品收益和风险等级分布等指标
- 信贷业务分析：查询贷款申请数、授信额度、有效贷款合同数、放款金额、贷款余额、审批通过率、合同状态和放款趋势等指标
- 还款与逾期分析：查询还款金额、还款计划、逾期余额、逾期合同数、提前还款、费用减免和还款完成情况等指标
- 风控与催收分析：查询风险事件数、规则命中数、人工复核任务数、黑名单记录、反洗钱案件、催收案件、催收回收率和处置结果等指标
- 维度分析：按时间、机构、渠道、客户类型、产品类型、风险等级、贷款类型、还款状态、逾期阶段、催收人员等维度统计和对比数据
- 结果返回：返回查询结果、统计结果、排名结果、趋势结果和必要的口径说明

## 5. 典型业务场景
### 5.1 客户与账户指标场景
当用户提出“本月新增客户数是多少”“当前正常账户数是多少”“不同风险等级客户分布如何”“哪个分行开户数量最多”之类的问题时，系统应返回对应客户和账户统计结果，并支持机构、渠道、客户类型和时间维度拆分。

### 5.2 交易经营分析场景
当用户提出“最近 30 天交易金额是多少”“本月交易笔数是多少”“失败交易笔数有多少”“哪个渠道交易金额最高”之类的问题时，系统应基于账户交易、渠道交易和对账数据完成统计、排序和结果返回。

### 5.3 理财业务场景
当用户提出“当前理财持仓规模是多少”“本月理财订单金额是多少”“哪个风险等级的理财产品销量最高”“近三个月理财赎回金额变化情况”之类的问题时，系统应返回理财产品、订单、持仓、收益和风险等级相关数据。

### 5.4 信贷与放款场景
当用户提出“本月贷款申请数是多少”“贷款审批通过率如何”“本月放款金额是多少”“当前贷款余额是多少”“哪个贷款产品申请最多”之类的问题时，系统应基于授信、贷款申请、审批、合同和放款数据完成统计分析。

### 5.5 还款与逾期场景
当用户提出“本月还款金额是多少”“当前逾期余额是多少”“逾期合同数有多少”“不同逾期阶段的金额分布如何”之类的问题时，系统应返回还款计划、还款记录、逾期记录和费用减免相关结果。

### 5.6 风控与催收场景
当用户提出“最近 7 天风险事件有多少”“命中最多的风控规则是什么”“人工复核任务数是多少”“催收回收率是多少”“哪个催收人员回收效果最好”之类的问题时，系统应返回风控规则、风险事件、人工复核、催收案件和催收绩效等统计结果。

### 5.7 趋势对比场景
当用户提出“最近三个月贷款余额变化情况”“本月和上月交易金额对比”“不同渠道的新增客户数对比”“各分行逾期余额排名”之类的问题时，系统应返回趋势数据、对比结果和排名结果。

## 6. 非功能需求
- 系统应具备基础异常处理和降级能力，避免分析失败导致整体服务不可用
- 系统应具备较好的可观测性，能够追踪问题解析、SQL 生成、查询执行和结果返回过程
- 分析结果应尽量准确、可解释、可追溯，能够说明使用的数据表、字段和统计口径
- 系统应支持同义词和业务别名识别，例如“客户数/用户数”“放款额/放款金额”“理财规模/AUM”“逾期余额/逾期金额”等表达
- 系统应支持后续扩展更多指标主题、分析规则、风险分析和经营看板能力
- 对金融金额类指标，应明确时间范围、币种、交易状态、订单状态和是否去重等统计口径
- 对涉及客户、账户、贷款、风控和催收的数据，应保留权限控制和敏感信息脱敏扩展能力

## 7. 项目交付物
建议输出以下成果：
- 一套可运行的金融问数系统
- 基础调试页面、测试脚本或演示页面
- 金融业务元数据说明，包括表名、字段释义、主外键关系、指标口径和常见问题模板
- 项目说明文档与部署说明
- 一组覆盖客户、账户、交易、理财、信贷、还款、风控、催收和运营场景的问数测试用例

## 8. 验收标准
- 可以完成新增客户数、活跃客户数、正常账户数、交易金额、交易笔数、理财持仓规模、贷款申请数、放款金额、还款金额、逾期余额、风险事件数、催收回收率等基础指标查询
- 可以完成按机构、渠道、客户类型、产品类型、风险等级、贷款类型、还款状态、逾期阶段、时间等维度的统计分析
- 可以完成趋势、对比、排名等常见分析请求
- 可以正确识别金融业务中的核心对象，例如客户、账户、交易、理财产品、贷款产品、贷款合同、还款计划、逾期记录、风险事件和催收案件
- 可以完成一次完整的“用户提问 -> 问题理解 -> 分析执行 -> 结果生成 -> 返回结果”的闭环演示
